# Pipeline schedule (plan — not built yet)

Two runs a day on GitHub Actions (cron is UTC; IST = UTC+5:30).

| Run | IST | cron (UTC) | Sources |
|---|---|---|---|
| Morning | 08:45 | `15 3 * * *` | LinkedIn (jobdrop), Indeed (jobspy), Naukri (jobspy), Google Jobs (jobdrop), Wellfound |
| Evening | 18:45 | `15 13 * * *` | LinkedIn (jobdrop), Indeed (jobspy), Naukri (jobspy) |

GitHub may start scheduled runs late (minutes, occasionally longer) under load.

## Fetch window

Per source, tracked in `state/last_success.json` (`window.py`):

- first run of a source: 72h
- afterwards: time since that source's last successful run, minimum 24h

So LinkedIn/Indeed/Naukri use 24h at both runs (≈10h/14h gaps are below the minimum,
so runs overlap — `seen_jobs.csv` removes repeats), and Google/Wellfound use 24h from
morning to morning. A missed run widens the next window automatically.

How the window is applied:

| Source | At fetch | In process.py |
|---|---|---|
| LinkedIn, Indeed | `hours_old = window` | date filter (day granularity) |
| Google Jobs | query text "since yesterday" / "in the last N days" | date filter |
| Naukri | no `hours_old` (relevance order) | date filter, Naukri-ID date when no date |
| Wellfound | not filterable (pages aren't date-sorted) | date filter on `liveStartAt` |

## Wellfound mode

`run_wellfound.py --mode auto`: **full** on Sundays (IST) — up to 10 pages per
role/location; otherwise **incremental** — up to 5 pages, stopping at the first page
whose job ids are all already in `seen_jobs.csv`.

## Actions jobs per run

Jobs run in parallel; each is billed separately, rounded up to the next minute.

| Job | Morning | Evening |
|---|---|---|
| `linkedin` (jobdrop venv) | ✓ | ✓ |
| `jobspy` — Indeed + Naukri in parallel lanes | ✓ | ✓ |
| `google` (jobdrop venv + Chrome) | ✓ | – |
| `wellfound` (requests only) | ✓ | – |
| `process` — merge, rules, dedupe vs `seen_jobs.csv`, commit `new_jobs.csv`, `seen_jobs.csv`, run summary | ✓ | ✓ |

The minutes estimate is in `production_report.md` (generated by `volume_report.py`).
